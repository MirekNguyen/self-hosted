# 2026-07-03 — Immich: Upgrade to v3.0.1 (chart 0.13.1)

## Summary

Upgraded Immich from `v2.7.5` (chart `0.12.0`) to `v3.0.1` (chart `0.13.1`), the first v3 major release.

## Breaking changes assessment

The Immich `v3.0.0` release and the immich-charts `0.13.0` release both carried breaking changes. Neither affects this deployment:

### 1. Immich v3 drops pgvecto.rs support — NOT AFFECTED

`v3.0.0` removes support for the deprecated `pgvecto.rs` database extension in favor of VectorChord. This deployment already runs VectorChord:

- DB image: `ghcr.io/tensorchord/cloudnative-vectorchord:16.9-0.4.3` (see `apps/immich-db.yml`)
- Postgres starts with `shared_preload_libraries=vchord.so` (see `charts/immich-db/templates/postgres.yml`)

The migration to VectorChord was already done in a prior session, so the primary v3 breaking change is a no-op here. We are also well above the `1.133.0` floor required after switching to VectorChord (no downgrade risk).

### 2. Chart 0.13.0 "values schema" (#382) — NOT AFFECTED

Chart `0.13.0` added JSON schema validation for `values.yaml` and switched publishing to release-please/OCI (#377). The existing `valuesObject` structure (`controllers.main.containers.main`, `immich.persistence`, `valkey`, `server`, `machine-learning`) remains valid under the new schema.

### 3. Third-party API changes — NOT AFFECTED

Most other v3 breaking changes are API endpoint updates that only affect third-party tools integrating with Immich's API. No such integrations are used here.

## Validation

Rendered the new chart against the exact existing values and diffed against the old render:

```
helm template immich oci://ghcr.io/immich-app/immich-charts/immich \
  --version 0.13.1 -f <existing-values> -n immich
```

- `helm template` exits 0 with no schema/validation errors
- Rendered images: `immich-server:v3.0.1`, `immich-machine-learning:v3.0.1`, `valkey:9.1-alpine`
- The **only** structural diff between the 0.12.0/v2.7.5 render and the 0.13.1/v3.0.1 render is the `helm.sh/chart` label version bump. Deployments, Services, Ingress, env vars, and volumes are otherwise byte-identical.
- `photos-pvc` library claim and `photos.mirekng.com` ingress preserved.

- DB image was left at `cloudnative-vectorchord:16.9-0.4.3` (VectorChord 0.4.3 is current for v3). Renovate manages further bumps.
