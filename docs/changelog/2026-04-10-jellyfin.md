# 2026-04-10 — Jellyfin: Subtitle burn-in proxy + encoding optimization

## Problem

Subtitles were not appearing when transcoding video at lower quality on mobile clients (Streamyfin v0.51.0, Fladder). Subtitles worked fine on direct play but were stripped entirely during transcode.

## Investigation

### Root cause: missing `AlwaysBurnInSubtitleWhenTranscoding` flag

The Jellyfin web UI stores `AlwaysBurnInSubtitleWhenTranscoding` in browser local storage and sends it in every `POST /Items/{itemId}/PlaybackInfo` request. This is a **per-request client-side parameter**, not a server-side setting.

- **Streamyfin** (TypeScript/React Native): Does NOT send the flag at all. Completely absent from `utils/jellyfin/media/getStreamUrl.ts`.
- **Fladder** (Dart/Flutter): Has the flag but only enables it conditionally: `alwaysBurnInSubtitleWhenTranscoding: isNativePlayer && isExternalSub`. For embedded ASS subtitles in MKV files, `isExternalSub` is false, so burn-in is never requested.
- Neither app exposes a user-facing setting to toggle this.

### Evidence from FFmpeg

All transcode commands included `-map -0:s` (stripping subtitle streams) with no `ass`/`subtitles` burn-in filter in the `-vf` chain. This confirmed the server was never receiving the burn-in flag from these clients.

## Solution: OpenResty sidecar proxy

Deployed an OpenResty sidecar container in the Jellyfin pod that intercepts all traffic before it reaches Jellyfin. For `POST /Items/*/PlaybackInfo` requests with JSON bodies, a Lua script injects `"AlwaysBurnInSubtitleWhenTranscoding":true` into the request body.

This is transparent to all clients and only affects transcoded playback (the flag is ignored during direct play).

### Traffic flow

```
Client -> Ingress (:443) -> Service (:8096) -> subtitle-proxy (:8097) -> Jellyfin (:8096)
```

### Files changed

- `apps/jellyfin.yml` — Added `subtitleProxy` values
- `charts/jellyfin/templates/deployment.yml` — Added sidecar container + configmap volume
- `charts/jellyfin/templates/service.yml` — `targetPort` changed from 8096 to 8097
- `charts/jellyfin/templates/subtitle-proxy-configmap.yml` — New: OpenResty config with Lua script

### Other changes

- User `binh` subtitle mode changed from "Smart" to "Always" via Jellyfin API (`POST /Users/{id}/Configuration`)

## Encoding optimization for Intel N150

Audited `encoding.xml` against hardware capabilities confirmed via `vainfo` output.

### Settings already correct

- `HardwareAccelerationType`: qsv
- `EnableHardwareEncoding`: true
- `EnableIntelLowPowerH264HwEncoder`: true (was fixed in earlier session)
- `EnableIntelLowPowerHevcHwEncoder`: true (was fixed in earlier session)
- `AllowAv1Encoding`: false (N150 has no AV1 encode HW)
- `EnableVppTonemapping`: true (QSV VPP for HDR->SDR)
- `EnableSubtitleExtraction`: true (was fixed in earlier session)
- `EnableFallbackFont`: true (was fixed in earlier session)
- All HW decode codecs enabled (h264, hevc, mpeg2, vc1, vp8, vp9, av1)

### Settings fixed today

| Setting | Before | After | Reason |
|---------|--------|-------|--------|
| `EnableAudioVbr` | false | true | Better audio quality at same bitrate |
| `EnableEnhancedNvdecDecoder` | true | false | NVIDIA-only, irrelevant for Intel |
| `PreferSystemNativeHwDecoder` | false | true | Prefer native QSV/VA-API decode path |
| `EnableSegmentDeletion` | false | true | Clean up old HLS segments, reduce disk I/O |

### Settings intentionally kept

| Setting | Value | Reason |
|---------|-------|--------|
| `EnableThrottling` | false | Throttling adds latency to seeks and initial playback. User priority is smooth, low-latency playback. |

## Intel N150 hardware reference

Confirmed via `vainfo --display drm --device /dev/dri/renderD128`:

- **Decode**: H.264, HEVC (8/10/12-bit, 4:2:2, 4:4:4, SCC), VP8, VP9 (all profiles), AV1, MPEG2, VC1, JPEG
- **Encode (slice)**: H.264, HEVC (8/10/12-bit, 4:2:2), MPEG2
- **Encode (low-power)**: H.264, HEVC (8/10-bit, 4:4:4, SCC), VP9 (all profiles)
- **No encode support**: AV1, VP8, VC1
- **VPP**: Video processing (tonemapping, scaling, deinterlace) supported
- **Driver**: Intel iHD 25.4.4, VA-API 1.22, oneVPL 2.15

## Decisions and tradeoffs

- Chose sidecar proxy over patching clients because neither Streamyfin nor Fladder exposes the setting and upstream fixes would take months.
- Kept throttling disabled despite the low-power CPU because user explicitly prioritized smooth playback and fast seeking over power savings.
- The encoding.xml lives on the PVC and persists across pod restarts, but is not managed by git. Changes to encoding.xml must be applied via `kubectl exec`.
