# 2026-10-28 — Hermes: migrate Dokploy/Hetzner → k3s, upgrade v2026.6.5 → v0.22.5

## Summary

`hermes.mirekng.com` (dashboard) and `gateway.mirekng.com` (API server) moved
from a Dokploy compose on Hetzner to k3s on the Beelink, all state preserved,
upgraded from `v2026.6.5` (0.16.0) to `v0.22.5` — the latest stable GitHub
release (27 releases in between; the project switched from CalVer to SemVer
at v0.21.6).

## Source (before)

- Dokploy project *Hermes*, compose `hermes` (`mhyyrKwd4Cn_099j1XNbe`),
  `nousresearch/hermes-agent:v2026.6.5`, `command: gateway run`, limits 4 GB / 2 CPU
- Volumes: `hermes-data` → `/opt/data` (1.8 GB, uid 10000), `hermes-root` → `/root` (2.3 GB caches)
- Env-driven secrets in Dokploy; DNS via `*.mirekng.com` wildcard → Hetzner

## Upgrade notes considered

- v0.22.0: memory providers (Hindsight) and Spotify moved to catalog plugins,
  auto-migrated on first start → backed up first; Hindsight still the provider afterwards.
- June 2026 dashboard hardening: non-loopback dashboard needs an auth
  provider. **Verified before cutover** in a throwaway pod: without config the
  dashboard did not bind 9119; with the real `config.yaml`
  (`dashboard.basic_auth`) it served `/login` 200 and `/api/*` 401.
- New entrypoint `entrypoint-dispatch.sh`: uses s6 `/init` when PID 1 —
  verified s6-svscan is PID 1 in k3s.
- v0.22.2 fixes gateway start after restarts (stale PID reuse) — relevant for k8s.

## Procedure

1. Smoke-tested `v0.22.5` on k3s with an emptyDir (also pre-pulled the image).
2. Wrote `charts/hermes`, `apps/hermes.yml`, `volumes/hermes.volume.yml`;
   `helm lint`, `helm template`, `kubectl apply --dry-run=server`.
3. Applied PVs/PVCs; helper pod (alpine + GNU tar + sqlite) mounting both PVCs.
4. Live pre-copy of `/root` caches (2.2 GB, 25 s) with `tar --numeric-owner`.
5. Created `hermes-secret` from the running container's env (piped, never
   printed); `API_SERVER_KEY` **replaced** by a new `openssl rand -base64 32`.
6. **Downtime start** — Dokploy `compose-stop` (exit 0, WAL checkpointed).
7. Backup `/root/backups/hermes-v2026.6.5-data-pre-k3s-migration-2026-10-28.tar.gz`
   (695 MB, 16 013 entries, sha256 alongside).
8. Full copy of `/opt/data` (17 s). Verified identical sha256 of `state.db`,
   `kanban.db`, `response_store.db`, `config.yaml`; 13 870 files / 2 098 dirs;
   ownership preserved (uid 10000, same 4 root-owned entries).
9. `PRAGMA integrity_check` ok on all three DBs. Baseline: 229 sessions,
   7 240 messages.
10. Pushed, synced. First start: config schema 27 → 51 (auto backups in
    `/opt/data/backups/config/`), dashboard ready, `✓ telegram connected`

    integrity ok, memory provider hindsight.
11. Pre-DNS test via `--resolve`: dashboard 302 → `/login`, `/login` 200,
    `/api/sessions` 401; gateway `/health` 200 (0.22.5); `/v1/models` 200

12. **DNS cutover** — A `hermes` (`ba6054da4f19c61821475e786b8bb9da`) and
    `gateway` (`355d8c4767293158260d8bde7e46fba0`) → `109.239.79.2`, unproxied.

Downtime: ~3 minutes (stop → Telegram connected), plus DNS TTL (300 s).

## Decisions

- **Rotated `API_SERVER_KEY`** — the old value was accidentally printed in an
  agent session (a `=$` grep matched its base64 padding). Nothing on Hetzner
  or in Open WebUI referenced `gateway.mirekng.com`; external clients must be
  updated with the new key (see `docs/hermes.md`).
- **`Recreate`, 1 replica** — single-writer SQLite + Telegram long polling.
- **Probes on gateway `/health`** with a 10-minute startup budget for migrations.
- **Kept `/root` volume** — only caches, but avoids a 1.4 GB camoufox re-download.
- **No capability drop** — s6 needs root to chown/drop to uid 10000, and the
  agent runs headless browsers; RuntimeDefault seccomp matches Docker's default.
- **1 GiB memory `/dev/shm`** — Docker's 64 MiB default is too small for Chromium.
- **CPU limit 2 / memory 4 GiB** — same as the Dokploy compose limits.
- Not exposed: host ports 8642/9119/43827 (Dokploy published them on the host
  as well); only the ingress is reachable now.
- `HERMES_SPOTIFY_CLIENT_ID` in values (public OAuth client id), everything
  else credential-like in the Secret, `TELEGRAM_ALLOWED_USERS` included.

## Rollback

1. Delete the `hermes` and `gateway` Cloudflare records (fallback to wildcard → Hetzner).
2. **Scale k3s Hermes to 0 first** (Telegram conflict), e.g. set `replicas: 0`
   in `apps/hermes.yml` and push.
3. `compose-start mhyyrKwd4Cn_099j1XNbe` in Dokploy (still v2026.6.5 with the
   original data and the **old** API key). State created after cutover is lost
   and the migrated config (schema 51) cannot be used by the old version.
